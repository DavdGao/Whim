# Feed source access research

Whim's required sources are Xiaohongshu, Zhihu, X, Reddit, GitHub Trending, arXiv and user-supplied URLs. This report records proposed routes for the macOS app as of November 11, 2026. Earlier anonymous probes and their limits are recorded in the [source inventory](research/feed-sources.md). Signed-in operations below still need an end-to-end trial.

## Search, subscriptions and rankings

Search takes a query and identifies the corpus searched. A subscription saves a source and selection (author, community, category, query or URL), then periodically checks for new or revised entries. A ranking captures a publisher's ordered list together with its scope, period and observation time. The same ranked board can itself be subscribed to.

| ------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |

Validate newest-first ordering and pagination before enabling background polling.                                 | Public board access unverified. Personalized recommendations would be a separate feed.                        |
| Zhihu               | Trial site search for questions and answers                                                      | Watch a question for new answers, or poll a saved search once ordering is verified                                                                                  | Trial the web hot-list route and preserve question order and observation time.                                |

## Acquisition choices

1. **Xiaohongshu.** Trial OpenCLI against a persistent Chrome profile for search and note detail. Agent-Reach delegates these operations to OpenCLI and retains the full detail link returned by search. An alternative is a local Xiaohongshu MCP server with its own login and session storage. Choose one backend per account so switching callers between the UI and agent does not trigger a second login. Expose only the required read operations. [Agent-Reach source](https://github.com/Panniantong/Agent-Reach/blob/main/agent_reach/channels/xiaohongshu.py), [MCP implementation](https://github.com/xpzouying/xiaohongshu-mcp)
2. **Zhihu.** Use direct HTTPS for the hot list if the endpoint passes a local probe. NewsNow requests the site's web JSON and extracts each question's ID, title and URL in response order. This web endpoint can change. Trial OpenCLI for search and question detail, including signed-out behavior. The public-board refresh should have its own availability state. [NewsNow adapter](https://github.com/newsnext/newsnow/blob/main/server/sources/zhihu.ts), [OpenCLI](https://github.com/jackwener/OpenCLI)
3. **X.** Prefer the official read API when the configured app can use the desired endpoint. Use app-only authorization where supported, or user OAuth with PKCE for user-context operations. Agent-Reach's experimental OpenCLI adapter is a candidate for interactive desktop use when explicitly configured. Prove search and timeline pagination separately. [X API](https://docs.x.com/x-api), [PKCE and offline access](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code), [Agent-Reach adapter](https://github.com/Panniantong/Agent-Reach/blob/main/agent_reach/channels/twitter.py)
4. **Reddit.** Evaluate the official Data API first with approved application access and an identified OAuth client. Verify access and applicable retention requirements before enabling ongoing collection. Test search, subreddit listings and pagination with the actual client. OpenCLI offers a separate browser-backed candidate for interactive reads. [Data API guidance](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki), [endpoints](https://www.reddit.com/dev/api/), [browser adapter](https://github.com/Panniantong/Agent-Reach/blob/main/agent_reach/channels/reddit.py)
5. **GitHub Trending.** Fetch the selected public Trending page and parse repository links in document order, as NewsNow does with Cheerio. Compare each period and language against the live page. Use official REST for optional repository search. The GitHub CLI and MCP server are useful references for search when a compatible credential is already configured. [Trending parser](https://github.com/newsnext/newsnow/blob/main/server/sources/github.ts), [GitHub CLI](https://cli.github.com/manual/gh_search_repos), [GitHub MCP](https://github.com/github/github-mcp-server)
6. **arXiv.** Use public HTTPS directly. The query API returns Atom entries and supports filtering and sorting. Category announcements have dedicated feeds. Keep source IDs and versions, cache responses and respect published access guidance. These public routes require no interactive sign-in. [Query API](https://info.arxiv.org/help/api/user-manual.html), [category feeds](https://info.arxiv.org/help/rss.html)
7. **Custom URLs.** Use an HTTP feed reader with conditional requests when validators are available. Accept ordinary publisher feeds and user-supplied RSSHub routes through the same reader. For a single page, compare the selected content across fetches and retain the last successful observation when extraction fails. Evaluate browser rendering only for sites that require it. Authenticated sites need an explicitly associated origin and account. [RSSHub](https://github.com/DIYgod/RSSHub), [changedetection.io](https://github.com/dgtlmoon/changedetection.io)

## Session reuse and recovery

Core should share one connection per source, backend and account across page searches, scheduled subscriptions and agent tools. CLI and MCP describe how Whim invokes a connector. Credential ownership determines whether a restarted connector can resume its session.

| Connection          | Reuse across restarts                                                                                                           | Automatic recovery                                                                                                                                                                             | When the user acts                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Public HTTP or feed | Persist only the subscription and fetch cursor                                                                                  | Honor Retry-After and retry transient failures with backoff                                                                                                                                    | Only when the publisher changes access requirements                                                                            |
| OAuth API           | Use Core's credential reference. Encrypt access and refresh tokens using the application's safeStorage path                     | Refresh once per account, sharing the in-flight refresh across callers. Persist rotated tokens before resuming work. Request offline access where supported, such as X's offline.access scope. | Revoked or expired refresh grant requires a new authorization. Missing endpoint entitlement requires access from the provider. |
| Browser-backed CLI  | Bind the adapter to the same dedicated persistent browser profile each time. Let the browser own its session cookies.           | Reconnect to the profile after a CLI or app restart. Run a read-only account check and allow the site's own session renewal.                                                                   | If the site asks for QR confirmation, MFA or another challenge, open the same profile for a single interactive login.          |
| Local MCP           | Configure a stable server identity and persistent session storage supported by that server. Let the server own its login state. | Reconnect the client and check upstream account status. A healthy MCP transport only establishes that the server is reachable.                                                                 | If upstream sign-in expired, use the server's login flow and resume through the same server.                                   |

A scheduled job that discovers expired authentication should pause the affected account's protected operations and show one reconnect action. After a successful identity check, resume from the last committed subscription cursor with overlap and item-ID deduplication. Account changes must bind to a separate cursor. Timeouts, empty results, rate limits and parser failures need distinct states to avoid prompting for login unnecessarily. Store no passwords for unattended form submission. Keep tokens, cookies and sensitive URL parameters out of traces.

## Verification before enabling a source

For each operation, compare IDs, destinations, order and pagination with the publisher's UI. Repeat a subscription refresh to check duplicates and verify an old board remains readable after failure. For each account-backed route, sign in once, restart Whim and the adapter, then run a search and a scheduled refresh using the same account. Exercise token rotation or browser expiry, concurrent refresh, logout, account switching and explicit revocation. Record which operations recovered silently and which required a person. Keep unverified operations unavailable until these trials establish their behavior.
