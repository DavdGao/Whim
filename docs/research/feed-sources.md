# Information sources for the Feed page

Research date: 2026-11-11. The proposed page has two entry points. Search sends a query to a selected source. Boards and subscriptions fetch a named collection without a query. A board preserves the publisher's order at the time of observation. A subscription generally orders entries by publication time. Searching Whim's saved entries would cover only the items already collected.

## Confirmed product scope

The minimum source set is Xiaohongshu, Zhihu, X, Reddit, GitHub Trending, arXiv, and user-specified pages or sites. The operations below are proposed targets. Authenticated operations have not been live-tested.

## What the existing projects contribute

**Agent-Reach and OpenCLI** address routing and setup. Agent-Reach groups platform operations and documents alternative backends. OpenCLI exposes site commands and can reuse the user's logged-in Chrome profile. For a desktop client the decisive check is whether the requested command works on this Mac with the current browser connection and account. A successful public search should enable that operation independently of protected operations.

**NewsNow and TrendRadar** address collection. NewsNow is a reference for mapping per-site results to a board display. TrendRadar collects boards and RSS on a schedule. Its documented MCP deployment can read the collector's stored output. A query against that output has a collection window and a last successful refresh time. Show both when presenting historical matches. [TrendRadar deployment](https://github.com/sansan0/TrendRadar#readme)

**RSSHub** turns site-specific routes into feeds. Supporting a user-supplied feed URL gives Whim access to ordinary publisher feeds and existing RSSHub deployments through one reader. Record the feed origin and distinguish publication time from observation time. A route that needs an upstream account may require configuration on the RSSHub host.

## Proposed first slice and acceptance

First validate one search and one pull path for each applicable required source. Start with public GitHub Trending and arXiv, then verify each social site's account requirements on macOS. Use a publisher feed and a changing standalone page to exercise both user URL modes. Hacker News, V2EX and Tavily remain optional additions.

Let the UI and agent invoke the same source operations. Each result needs its source, upstream ID or stable link, title and destination. Search also carries its query and pagination state. A board snapshot carries its board ID, period if applicable, fetch time and ordered item references. The same story can appear on several boards and at different ranks over time. Persist an item once per source and retain its separate appearances. Source failures should leave the last successful board visible with its age. An explicit empty result and an unsuccessful refresh need distinct UI states.

Before shipping, test repeated refresh, rank movement, overlap across pages, removed entries, an unreachable source, throttling and expired login. For an authenticated adapter, verify sign-in, search, logout and recovery on macOS. For Trending, compare extracted names and order against the page for the same period. Accept a new adapter only after verifying its actual item links, ordering and authentication behavior.

## Probe scope

Anonymous HTTP requests from the development Mac on the research date returned HTTP 200 for HN Algolia story search (`sqlite`), HN Firebase Top (500 IDs), HN RSS (RSS XML), GitHub REST repository search (`sqlite`), GitHub Trending daily (HTML), and V2EX Hot (9 items). These probes establish reachability and response shape at one point in time. Pagination, ranking fidelity, sustained polling, authenticated CLIs and MCP sessions still require integration tests.
